# TypeScript 5.5: Inferred Type Predicates and What Else Changed

TypeScript 5.5 was released in mid-2024 but its features are worth revisiting — especially inferred type predicates, which resolve one of the most common friction points in typed filtering.

## Inferred Type Predicates

Before 5.5, TypeScript could not automatically infer that a function is a type predicate. You had to write the return type manually:

```ts
// Before 5.5 — manual type predicate annotation required
function isString(value: unknown): value is string {
    return typeof value === "string";
}

const items: (string | null)[] = ["hello", null, "world", null];
const strings = items.filter((x): x is string => x !== null);
//                                ^^^^^^^^^^^^^ needed manually
```

In TypeScript 5.5, the type predicate is **inferred automatically** from the function body:

```ts
// TypeScript 5.5 — no annotation needed
function isString(value: unknown) {
    return typeof value === "string";
}
// Inferred return type: value is string ✅

const items: (string | null)[] = ["hello", null, "world", null];
const strings = items.filter(x => x !== null);
// strings is string[] ✅ — TypeScript infers the narrowing
```

This is particularly impactful for `.filter()` calls, which have historically required explicit type predicates to narrow the result type.

## More Filter Examples

```ts
// Filtering out undefined
const maybeUsers: (User | undefined)[] = fetchUsers();
const users = maybeUsers.filter(u => u !== undefined);
// users: User[] ✅

// Filtering by type
type Shape = Circle | Square | Triangle;
const shapes: Shape[] = getShapes();
const circles = shapes.filter(s => s.kind === "circle");
// circles: Circle[] ✅ (if Circle has kind: "circle" discriminant)
```

## Isolated Declarations

`--isolatedDeclarations` is a new compiler option that requires all exported symbols to have explicit type annotations. This enables tools and bundlers to transform individual files **without full program type-checking** — a significant performance win for large codebases.

```json
{
    "compilerOptions": {
        "isolatedDeclarations": true
    }
}
```

With this flag, TypeScript errors if an exported value's type isn't explicitly annotated:

```ts
// ❌ Error with isolatedDeclarations
export const config = { port: 3000, host: "localhost" };

// ✅ OK
export const config: { port: number; host: string } = {
    port: 3000,
    host: "localhost",
};
```

This powers faster `.d.ts` generation in tools like `esbuild`, `swc`, and Vite. Libraries in particular benefit from adopting it.

## Regular Expression Syntax Checking

TypeScript 5.5 validates regular expression syntax at compile time:

```ts
// ❌ Error: Invalid regex — unmatched parenthesis
const pattern = /foo(bar/;

// ❌ Error: Invalid flag
const invalid = /foo/z;

// ✅ Valid
const valid = /^https?:\/\//i;
```

TypeScript won't catch all regex logic errors, but it catches syntax errors that would throw at runtime.

## `${configDir}` in `tsconfig.json`

A new template variable in `tsconfig.json` paths:

```json
{
    "compilerOptions": {
        "paths": {
            "@/*": ["${configDir}/src/*"]
        }
    }
}
```

`${configDir}` resolves to the directory containing the `tsconfig.json` file. This makes path mappings correct when extended configs are used across different package directories in a monorepo.

## Performance Improvements

TypeScript 5.5 includes significant type-checking speed improvements, particularly for:
- Large union types
- Complex conditional types
- Projects with many `@types` packages

Benchmarks show 10–50% faster type-checking in some large codebases.

---

The inferred type predicates feature alone makes TypeScript 5.5 worth the upgrade. The `.filter()` pattern improvement removes hundreds of manual type annotations from typical codebases.
