# JavaScript Pattern Matching: The `match` Proposal Explained

JavaScript's `switch` statement is limited: it only supports strict equality comparisons, it falls through by default, and it can't destructure values. The **pattern matching proposal** (Stage 2 as of 2025) introduces a `match` expression that fixes all of this.

## What `match` Does

`match` is an **expression** (not a statement) that returns a value. Each arm uses `when` and can match against patterns, not just values:

```js
const result = match(response) {
    when ({ status: 200, body }): `Success: ${body}`,
    when ({ status: 404 }): "Not found",
    when ({ status: 500 }): "Server error",
    default: "Unknown status",
};
```

Contrast with `switch`:

```js
// switch — statement, not expression, no destructuring
switch (response.status) {
    case 200:
        result = `Success: ${response.body}`; // Can't access body inline
        break;
    case 404:
        result = "Not found";
        break;
    default:
        result = "Unknown status";
}
```

## Pattern Types

### Literal Patterns

```js
const label = match(statusCode) {
    when 200: "OK",
    when 201: "Created",
    when 204: "No Content",
    default: "Other",
};
```

### Destructuring Patterns

```js
const message = match(action) {
    when ({ type: "INCREMENT", amount }): `Add ${amount}`,
    when ({ type: "RESET" }): "Reset to zero",
    when ({ type: "SET", value }): `Set to ${value}`,
    default: "Unknown action",
};
```

### Array Patterns

```js
const desc = match(args) {
    when []: "No arguments",
    when [x]: `One argument: ${x}`,
    when [x, y]: `Two arguments: ${x} and ${y}`,
    default: `Many arguments`,
};
```

### Guard Clauses (`if`)

Add conditions beyond structural matching:

```js
const tier = match(score) {
    when n if (n >= 90): "A",
    when n if (n >= 80): "B",
    when n if (n >= 70): "C",
    default: "F",
};
```

### Matching Multiple Patterns (OR)

```js
const isRedirect = match(status) {
    when (301 or 302 or 307 or 308): true,
    default: false,
};
```

## Real-World Example: State Machine

```js
function reducer(state, action) {
    return match(action) {
        when ({ type: "FETCH_START" }): {
            ...state,
            loading: true,
            error: null,
        },
        when ({ type: "FETCH_SUCCESS", data }): {
            loading: false,
            data,
            error: null,
        },
        when ({ type: "FETCH_ERROR", error }): {
            loading: false,
            data: null,
            error,
        },
        default: state,
    };
}
```

This is equivalent to a long if/else chain but far more readable and exhaustive.

## Custom Matchers

You can define custom matchers using `Symbol.matcher`:

```js
class Range {
    constructor(min, max) {
        this.min = min;
        this.max = max;
    }

    static [Symbol.matcher](value) {
        return {
            matched: value >= this.min && value <= this.max,
            value,
        };
    }
}

const tier = match(score) {
    when Range(90, 100): "Excellent",
    when Range(70, 89): "Good",
    when Range(50, 69): "Average",
    default: "Below average",
};
```

## Current Status and Polyfill

The proposal is **Stage 2** and not yet natively available. You can experiment with it via:

```bash
npm install @tc39/proposal-pattern-matching
```

Or with the Babel plugin:

```bash
npm install --save-dev babel-plugin-proposal-pattern-matching
```

The syntax may change before finalization — do not use in production without understanding the proposal is pre-Stage 3.

---

Pattern matching will eliminate entire categories of verbose `if/else` chains and `switch` statements. Watch the TC39 proposal closely — it's one of the most impactful additions coming to the language.
