# CSS View Transitions: Native Page Animations Without a Framework

Animated page transitions have required JavaScript animation libraries or full-stack frameworks. The **View Transitions API** — now supported across all major browsers — provides this natively, with a few lines of CSS.

## How It Works

The API works in two phases:

1. **Capture**: The browser takes a snapshot of the current state.
2. **Transition**: The browser renders the new state and animates between them using CSS.

## Single-Page Application (SPA) Transitions

For SPAs (including Next.js with client navigation), wrap state updates in `document.startViewTransition()`:

```js
document.startViewTransition(() => {
    // Update the DOM here
    updatePageContent(newContent);
});
```

Or in React, trigger it before navigation:

```js
function navigate(href) {
    if (!document.startViewTransition) {
        window.location.href = href;
        return;
    }
    document.startViewTransition(() => {
        window.location.href = href;
    });
}
```

The browser automatically applies a cross-fade animation between old and new states. No CSS required for the default.

## Multi-Page Application (MPA) Transitions

For traditional multi-page apps, add this to your CSS — no JavaScript needed:

```css
@view-transition {
    navigation: auto;
}
```

That's it. Every page navigation in your site will now cross-fade.

## Customizing the Transition

The browser creates two pseudo-elements during the transition:

- `::view-transition-old(root)` — snapshot of the outgoing page
- `::view-transition-new(root)` — snapshot of the incoming page

Override their animations:

```css
/* Slide in from right */
@keyframes slide-in {
    from { transform: translateX(100%); }
    to { transform: translateX(0); }
}

@keyframes slide-out {
    from { transform: translateX(0); }
    to { transform: translateX(-100%); }
}

::view-transition-old(root) {
    animation: slide-out 0.3s ease-in;
}

::view-transition-new(root) {
    animation: slide-in 0.3s ease-out;
}
```

## Named View Transitions (The Morphing Effect)

This is where it gets powerful. Assign a `view-transition-name` to an element on both pages, and the browser morphs between them:

```css
/* On the list page */
.product-thumbnail {
    view-transition-name: product-image;
}
```

```css
/* On the detail page */
.product-hero {
    view-transition-name: product-image;
}
```

When navigating between pages, the thumbnail smoothly transforms into the hero image — position, size, and shape all animate. This previously required complex JavaScript with `getBoundingClientRect()` calculations.

> **Rule**: Each `view-transition-name` must be unique in the DOM at any given time. For lists, generate dynamic names:

```css
.product:nth-child(1) { view-transition-name: product-1; }
.product:nth-child(2) { view-transition-name: product-2; }
```

Or in JavaScript:

```js
products.forEach((el, i) => {
    el.style.viewTransitionName = `product-${i}`;
});
```

## Respecting User Preferences

Always respect `prefers-reduced-motion`:

```css
@media (prefers-reduced-motion: reduce) {
    ::view-transition-old(root),
    ::view-transition-new(root) {
        animation: none;
    }
}
```
